A Prolog for Strata, written in Strata assembly and running as a StrataOS program. Strata's memory is explicit I/O, and Stralog's engine is built around that: every term lives in far memory, reached only by transfers, and the data Local Store holds windows onto the tops of its stacks and a small far cache. The playground runs StrataOS in the WebAssembly emulator with stralog started: press Try on an example.

OverviewWhat it is

ISO core Prolog in one namespace: cut, if-then-else and soft cut, negation, call/N, catch/throw with ISO error terms, assert/retract under the logical update view, findall/bagof/setof, DCGs, op/3, files, lambdas for maplist and its kin. Integers have 61 bits (an overflow is an evaluation_error); there are no floats, bignums or modules.

strata$ stralog
Stralog 0.1
?- X = f(Y), Y = 3.
X = f(3), Y = 3.
?- [family].
true.
?- ancestor(A, jim).
A = pat ;
A = tom ;
A = bob ;
false.
?- findall(D, ancestor(tom, D), Ds).
Ds = [bob,liz,ann,pat,jim].

The engine

The engine is a structure-copying interpreter in Strata assembly, every line commented.

  • Clauses are compiled once, when they are consulted or asserted, into templates in a clause store.
  • A call unifies the goal with the head's template, building only what it binds.
  • The body becomes a continuation term on the heap.
  • First-argument indexing keeps most deterministic calls from leaving a choicepoint.
  • Where the code lives: the solve loop, unification and the memory code are resident. The reader, the writer, arithmetic and the builtins are 4 KiB code units that StrataOS pages into the instruction Local Store when they are called.
  • Written in Prolog: the top level, consult, the list library, sorting, bagof and DCG translation are in boot.pl, which travels in the image and is consulted at start-up.

Memory is explicit

  • Cells: a cell refers to other cells by arena offset, never by Local Store address.
  • Windows: the heap, the trail and the choicepoint stack each have a window in the data Local Store over their top:
    • a push past a window's end writes its lower half out with an asynchronous tput, and nothing waits for it;
    • backtracking frees heap without any transfer, because everything above the restored top is dead;
    • the next push below the window slides it down, reading back at most one line.
  • The far cache: everything else goes through a 4 KiB write-back cache on the hardware's tag table (ltag/linst): older cells, the atoms, the clauses, the findall answers.
  • Garbage collection: a sliding mark-and-compact collector runs between goals, through the same paths. It tidies the trail first, so that entries left behind by cuts keep nothing alive.
  • What moved: statistics/0 shows it.

Running it

  • stralog opens the top level.
  • stralog FILE ... consults files first.
  • stralog -g GOAL FILE ... runs a goal and halts.
  • -m 8 stralog gives it an 8 MiB arena, about 7 MiB of heap.

The top level and read/1 read through a line editor: Backspace, Ctrl-U, ↑ and ↓ for earlier lines, and Ctrl-D, which ends [user]. After an answer that may have others, ; asks for the next one.

The examples are on the disk under /stralog, and [queens] finds them there.

The conformance vectors are ISO's and Szabó and Szeredi's, by way of Logtalk's tests (Apache-2.0); 584 of the 596 that fit Stralog pass. The README lists the twelve that do not.
