Stratalk

{{classes}} classes{{methods}} methods{{ops}} StrataOS messages as methodsgenerated from the sources

A Smalltalk for Strata, running under StrataOS, whose object memory follows the machine: a core computes only on its Local Stores, and everything else is reached with explicit transfers. New objects are made in a nursery in the core's data store and the survivors are written out to far memory in one transfer; far objects are read through a software cache; frames page out to a far stack when recursion goes deep; native code compiled by a JIT written in Stratalk is paged into the instruction store on demand. The playground runs StrataOS with the real stratalk in the WebAssembly emulator: press Try on an example.

OverviewWhat it is

Smalltalk-80 with Pharo's syntax, class library and exceptions: classes and metaclasses, blocks that are full closures with non-local return, on:do:, ensure:, resume:, retry, pass, SmallIntegers of 63 bits that grow into large integers, strings, symbols, collections and streams. Programs are files of class definitions, methods and statements, edited with vi and run with stratalk FILE.st; the image is a cache built from the kernel's own files, never the only copy of anything.

Running it

  • stratalk: the REPL. What you type is shown as you type it; Tab completes a class or global name after a capital letter and a selector otherwise (the receiver's, when the line shows it: 3 facTab), and lists the choices when there are several; the arrows go back through the lines typed.
  • stratalk -e EXPR prints one result; stratalk - reads expressions from a pipe; stratalk FILE.st files a program in.
  • stratalk -j: with the JIT on.
  • In the window server: stratalk -w opens a workspace (Ctrl-P prints the current line's value, Ctrl-D does it, Ctrl-O inspects it, Ctrl-B browses), stratalk -b a class browser (the classes, their selectors, a method's source, which Ctrl-S compiles), and anObject inspect an inspector.
  • The examples are on the disk under /stratalk/examples; the kernel's sources under /stratalk.

The modelObjects

Everything a program handles is an object, and everything it does is a message sent to one: an object answers a message by running the method its class has for the selector, or its superclass's, up to Object. The class reference below is these classes, each method's description first and its source after it.

  • An object is a header word and slots. The header holds its class (as an index), its format (named slots, indexed slots, bytes, compiled code or raw words), whether it is immutable (literals are), its identity hash and its size. SmallIntegers and Characters are not allocated: the reference itself holds the value. nil is the reference 0.
  • A class is an object too: an instance of Class, with its name, its superclass, the names of its slots, its format and a MethodDictionary from selectors to methods. Object subclass: #Point slots: 'x y' makes one; variableSubclass:, byteSubclass: and wordSubclass: make indexed ones. Inheritance is single.
  • A metaclass is the class of a class: Point class, whose one instance is Point. It holds the class-side methods (Point class >> x: ax y: ay [ ... ]) and the class-side slots (Point class slots: 'count'), which stand in for class variables. Every metaclass is an instance of Metaclass: 3 class is SmallInteger, 3 class class is SmallInteger class, and 3 class class class is Metaclass.
  • A block, [:x | x + 1], is a BlockClosure: the compiled block, the receiver, the frame of the method it was made in, and the values it captured (captured variables that are assigned live in a shared vector instead). value: runs it; ^ inside it returns from that method, and signals BlockCannotReturn if the method has returned already.
  • A method is a CompiledMethod: a header (arguments, temps, literals, primitive number), its literals (the last two are its selector and its class) and its bytecodes. Methods are compiled from the source files by the compiler in the image (Compiler.st), or on the host when the image is built; one that is run often is compiled again to Strata code by the JIT. Point >> #x answers one.

Where an object lives is in its reference: a near object is in the core's data Local Store, which the core reads and writes directly; a far one is in the far heap, which it reaches with transfers. New objects are made near and most die there; the ones that survive a nursery collection are copied out and become far. Symbols, classes, methods and objects over 2 KiB are made far from the start. isNear tells:

st> (3 @ 4) isNear
true
st> (Array new: 1000) isNear
false
st> #foo isNear
false
st> (Point >> #x) isNear
false

A program never sees the difference otherwise: a near object stored into a far one is remembered and goes out to the far heap at the next collection, and a far one is read through the VM's cache. What it costs shows in Smalltalk vm.

The VMNear and far objects

The virtual machine is a bytecode interpreter in Strata assembly: about 22 KiB of the program's 32 KiB of instruction store, 38 KiB of its 40 KiB of data store. The interpreter keeps its instruction pointer, frame, receiver, nursery and caches in registers for the whole run.

  • Where an object lives shows in its reference. Low bits 010: a near object, in the D-LS; 000: a far object, an offset in the far heap (an extra arena from proc); bit 0: a SmallInteger; 100: a Character.
  • New objects are near: bumped in an 8 KiB nursery. Most die there and never cost a transfer.
  • Promotion is the write-out. When the nursery is full the scavenger marks what the stack and the remembered far slots reach, gives each survivor its far address, points every reference at it, slides the survivors together and copies them out in one tput.
  • Far objects are read through a software cache of 64-byte lines on the hardware's ltag/linst. Every far store goes through it and out: write-through, a transfer per store. A near reference stored into a far object is remembered.
  • The full collector marks the far heap and sweeps it by streaming its headers through the cache; dead runs become free chunks, allocated first fit. Nothing moves.
  • Methods run from a method cache in the D-LS, each copied in with one tget; a send looks in a (class, selector) cache, then walks the method dictionaries in far memory.
  • The stack pages. Frames live on the program's 8 KiB stack and are named by logical addresses. When an activation would not fit, the frames above the current one go out to a far stack in one transfer (after a scavenge, so nothing near goes out); returning into them brings them back. Recursion goes about 15,000 frames deep before StackOverflow.

Smalltalk vm shows the figures: sends, far cache misses, bytes read and written, scavenges, bytes promoted, full collections.

Native codeThe JIT

A method activated 200 times is offered to the JIT, which is Stratalk code: it translates the bytecodes template by template into Strata code that keeps the interpreter's frames and registers, with the operands as constants and no dispatch. Temps, literals, jumps, == and the SmallInteger cases of arithmetic and comparisons are done in place; sends, returns and allocation call the resident VM.

  • Code is paged, as memory is. Each compiled method gets a 1 KiB code unit in the program's arena; StrataOS pages units into the instruction store on a miss.
  • Returns are far links. A send from native code records the far address to come back to; the return uses xret, which pages the caller's unit back in if it was evicted meanwhile.

StrataOSEvery server, as classes

A process talks to StrataOS by messages to servers. OSServers.st is generated from the servers' specifications (os/spec/*.toml): a class per server (ProcServer, FsServer, DbServer, WsServer, ...) and two methods per operation, one without arguments and one that takes a Dictionary of the request's fields by their spec names. The reply decodes its data by the spec. Friendlier faces sit on top:

Proc ps                          "the processes"
ProcServer default info fields   "cores, memory, context switches"
Fs statfs                        "#(blocks used files)"
(Db tree: 'mine/notes') at: 'k' put: 'v'; at: 'k'
(File named: '/doc/motd') contents
(Window open: 'demo') text: 'hello' column: 2 row: 1 color: 16rFFFFFF background: 0
