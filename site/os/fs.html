StrataOS 0.1 · the file system

FILES AS A STORE

The disk holds nothing but ordered trees, written copy-on-write: a power cut leaves the last commit or the next one, never a mixture. A file has one name and any number of tags, and a directory is the set of its files' tags.

01The store

fs is built on a store: B+trees of keys and values in 4 KiB pages, grouped in namespaces, every page with a checksum. The file system is one client of it, with five trees in the private namespace fs; programs keep trees of their own beside it.

02A directory is a set of tags

There are no directories on the disk. A file has one name and carries tags; the set of its tags is its directory. A file tagged src and demo is in /src/demo, which is also /demo/src; a file with no tag is in the root. A name is unique within a directory, so /src/x, /src/demo/x and a root x are three files.

  • Paths. Every name fs takes is a path: the last component is the file's name, the ones before it are its directory's tags. Opening for writing makes the file there, making the tags that do not exist yet. -tag excludes in a listing: ls /src/-demo.
  • Subdirectories are facets. QUERY lists a directory's files and, as a tag set, the other tags carried by the files of deeper directories: ls /src shows demo/.
  • The current tag path is the tag-system analogue of a working directory, one per process, inherited from the parent (proc sends CWD while it spawns).
  • Moving is retagging. TAG and UNTAG move a file into the directory with or without the tags; RENAME takes a new path's name and tags.
  • Searching is a seek. FIND mode 0 seeks the names' tree at the text in each directory in turn; mode 1 reads records in object order, 384 at most per part, so that a part may come back empty with a cursor and the asker can stop between parts. The file navigator nav searches the whole disk as you type this way.

Writing, whole or not at all

Opening for writing sends the bytes to a blob of their own; the close puts it in place of the file's contents and commits, so the disk holds the old contents or the new. UNLINK, TAG, UNTAG and RENAME are a commit each: when the reply arrives, the change is on the disk. A boot object (proc, dev, fs, blk, db) can be rewritten from inside the OS: at its close it is brought into one run of pages and the manifest is written anew in the same commit, so the next boot loads the old server or the new one.

Snapshots, attributes, trees for programs

  • Snapshots (SNAP; snap NAME): the whole disk as of a commit, copying nothing. A page that a snapshot still shows is not freed but goes to that snapshot's dead list. A path beginning @NAME reads the snapshot: cat /@monday/notes. Restoring is one commit.
  • Attributes (SETATTR, GETATTR; attr): a name and a number or string per file, in its record and in the index. A path component with =, < or > is a condition: ls /src/lang=asm, ls '/src/size>100000'; PREFIX* matches names.
  • Trees for programs (DBGET, DBSCAN, DBBATCH; db): keys and values in a namespace of a program's own, answered by db: a program sends DBGET and DBSCAN to it directly, or any of the three to fs, which forwards them. A batch is one commit: all of its items are on the disk, or none.
