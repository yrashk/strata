StrataOS 0.1 · the kernel

THE KERNEL

A system core that creates processes, hands out memory and keeps time, and a dispatcher on every other core that runs its threads. A few kilobytes stay resident; the rest is paged in on demand.

01svc: asking the dispatcher

svc is a process's one way into the kernel: in user mode it traps to the supervisor, its core's dispatcher, with the function in a0. A program never calls the kernel for files or the console; it sends a message and waits with an svc. Timeouts are in ticks of 1 µs, −1 for none; the result comes back in a0.

A program puts the function in a0 and its arguments in a1..a5, and runs svc. The dispatcher of its core answers: the result comes back in a0 (an unknown function gives −1), and some calls also set a1 or a capability register. Timeouts are in ticks of 1 µs; −1 means none, and 0 times out at the next look. A call that blocks lets the core run its other threads.

1WAIT_REPLYWait for a reply, for an awaited capability, or sleep

The caller has just sent its buffer (c5) with csend. The dispatcher rings the destination's doorbell and blocks the caller until the buffer comes back, or until a capability with the awaited base arrives. With a3 = −1 nothing is awaited: the call is a sleep that only the timeout or an interrupt ends. A capability that arrives for a register holding a live linear one is dropped.

02The system core's operations

Core 0 answers messages too, through an endpoint only proc holds (and dev, to halt the machine and to lend the framebuffer). Policy lives in proc; these are the mechanisms it asks for. When a process ends, the kernel sends proc op 7 EXITED (handle = pid, length = its status).

Core 0 runs no programs: it answers these requests in its own event loop, with code units it pages in itself. The sender's pid comes from the arena its buffer lies in (proc is pid 1, dev pid 2), and the ops that only one of them may send check it. A capability sent with a request goes just before the message (the arena of CREATE, FREE, GSTART); the capabilities of a reply arrive in the caller's c6. The reply sets only the header's result word. The kernel also sends proc op 7 EXITED when a process ends (described with proc).

1CREATEStart a process in an arena that holds its image

The kernel reads the image's STX headers, chooses the cores and slots, and starts the threads. A StrataOS program (code word 1 "SYS2") with 0 threads is one thread without a core window; a bare-metal program, or any program with N threads, gets N threads on N contiguous worker cores seen through its core window. A StrataOS program that is not a server also gets its console ring (RINGS) in c6.

03Scheduling and time slices

Every process time-shares worker cores; there are no exclusive cores. Each worker runs up to 16 threads of different processes. The system core owns the timer, whose DEADLINE register is a device read that completes at a time: every time slice (2 ms by default; TUNE, or sched at the shell, sets 100 to 100,000 ticks) it stops, through core control, each worker that has more than one runnable thread. A core running a single thread is never interrupted. The same timer runs every timed wait: the earliest deadline of each core is in the KST.

  • Placement. A server goes on the lowest core that has none. A one-thread process goes on the least loaded worker, preferring cores that hold a server; N threads go on the run of N contiguous server-free cores whose busiest core is least loaded. SPAWN can pin a process to a core (the shell's -c N).
  • Slots, not surprises. A switched-out thread's capabilities must stay on its core, in the core's capability save table (256 slots). Every thread record has 10 slots reserved, all a thread could ever need; the general part holds the queues. Nothing runs out, so placing a thread on a core with a free record is placing it where its slots are.
  • Limits. 64 processes and 64 arenas, 46 MiB of arena pool, 8 handles per process, 6 threads per process.

04The context switch, and what it moves

A thread's state is its registers, its capability registers, its CSRs and the parts of its Local Stores it uses. Nothing hides the cost of moving them: the dispatcher copies them, and counts every switch and every kilobyte.

  1. Drain the thread's transfers (every tag but the dispatcher's own).
  2. Registers: x1–x31 and the CSRs into the thread's record (on every trap, not only switches).
  3. Capabilities: c0–c7 are the thread's across switches. An endpoint or a device capability is described and made again on switch-in; memory goes into a save-table slot. c8–c15 belong to it only while it is not switched out.
  4. Out: the data extent (a program's data section; for a bare-metal program all of 0–0x9FFF) and the live stack (sp–0x10000) go to the save area in its arena. Not the whole 64 KiB, and not a scratch range the thread declared (SET_SCRATCH).
  5. In, code: B's code reloaded from its image (or from the code mirror a JIT declared with SET_MIRROR), and the code units its cache held put back into their slots and mapped.
  6. In, data: B's data and stack; when another process ran on this core in between, or at B's first load, the whole program D-LS (48 KiB), so that no process sees another's bytes. Then capabilities, registers, eret.

Every atomic of the switch (the counters, the published slot states, the running pid) is made before its first transfer, because a far atomic waits for the core's transfers to finish. Each dispatcher times itself with the cycle CSR; cores shows cycles per switch and per trap. Measured on the Verilog RTL over a scripted session, a switch took about 10,000 cycles and an average trap about 15,000.

05Demand paging of code

Instructions come only from a core's 64 KiB instruction Local Store, and stores cannot write it. Code that does not fit is cut into code units in far memory, called with xcall through a capability: the overlay map translates a far address to a slot of the I-LS, and a call to a unit that is not mapped traps with xmiss.

  • The kernel pages itself. Only I-LS 0x4000–0x7FFF is resident. Start-up, the system core's operations, exits and ticks are 2 KiB units of the kernel's far image, paged by core 0's own trap handler into 16 cache slots at I-LS 0x8000 (round robin). After start-up the units are copied into T2, where one starts arriving after 4 bus cycles instead of 20. uptime counts the units paged in.
  • Programs page too. A program's code cache is the I-LS after its resident code; on a miss the dispatcher pages the unit in from the program's arena. The record keeps the unit of every slot, and a switch-in puts them back: the cache is part of a thread's state like its D-LS. The C compiler is 106 KiB of code running in a 32 KiB instruction store this way. svc UNITS reports the paging; svc PAGE serves a program that has a trap handler of its own.

Source: the paging trap k_trap and page_in in os/kernel.s · Chapter 18, StrataOS

06Capabilities, endpoints, revocation

Far memory, device ports and other cores are reachable only through capabilities, and the kernel hands out every one a process holds. A StrataOS program starts with:

c0
its arena's program memory (832 KiB with one thread)
c1
a send-only endpoint to proc: the one it is always born with
c2, c3, c4
endpoints to fs, tty and pipe (absent in a child spawned sandboxed)
c5
its 4 KiB message buffer, the last 4 KiB of the arena
c6
empty: capabilities that arrive with a reply land here (and in c7)
c7
the clock: a read-only device capability to the timer's NOW and FREQ; reading the time is an 8-byte tget
  • Linear memory. A writable memory capability cannot be copied, only split, joined, given and taken. A message buffer is lent: while a server holds it, the client does not. A data race on it cannot be written down.
  • Endpoints name a core. The kernel mints them (cmkep) for the core where a server runs; user processes never get receive rights, so a core's inbox belongs to its dispatcher. proc hands out endpoints by name (LOOKUP); a server registers its name (REGISTER). An endpoint is rebuilt on switch-in, so it costs no save-table slot.
  • Revocation by address. Only the kernel makes memory revocable (cdom, crevoke are privileged). The arena pool and the framebuffer are revocable regions with a generation per 256 KiB granule. An arena is cut out by revoking that piece of the pool, which yields a fresh capability; when its process ends it is revoked again and everything cut from it or lent out dies, a request a server was holding included.

07Interrupts are device reads

Strata has no interrupts. A device makes something happen by completing a transfer, and tany waits for any of a set of transfers, or for a capability arriving in the inbox.

  • The timer is a read of DEADLINE that completes at a time. The system core keeps one in flight for the next slice or the earliest timed wait.
  • Ctrl-C is a read of the console's break port, which tty always keeps in flight; it completes when the key is pressed, and tty asks proc to SIGNAL the foreground process.
  • A server waits on its devices and its clients at once. svc RECEIVE takes a mask of transfer tags: tty names its break read and its input read, net its receive read. A server that keeps a device read waiting is alone on its core, since a switch would have to wait for it.
  • Doorbells. After a send, the sender's dispatcher writes a stop into the destination core's core-control word, so that core's dispatcher runs within microseconds instead of at the next tick. A core idle in tany wakes on its inbox anyway.
  • Halting completes the reads still pending: the system core waits for every dispatcher to stop its threads, then writes the console's release port, the pointer's EVENT port, the network interface's CANCEL and DEADLINE 0, and halts.
