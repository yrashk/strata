01Two compilers, one fixed point

A new machine has no C compiler to compile its C compiler with. Strata's answer is the old one: write the first compiler by hand, in assembly, and let it compile the real one.

lang/cc/cc.c is the compiler: the cc of StrataOS, written in the C it compiles. lang/cc/cc.s and the files beside it are the bootstrap compiler, cc0: the same language again, in Strata assembly.

Both are on the disk, with the compiler's source, so the bootstrap can be run where it belongs, on the machine. One test of the build does exactly that, and compares the results byte for byte.

  • cc1 differs from c2: other compiler, other code
  • c2 and c3 are the same files: the compiler reproduces itself
  • They are also the cc on the disk, which was built on another machine
strata$ cc0 -p -h 0 -o cc1 /src/cc.c   # the assembly compiler compiles cc.c
strata$ cc1 -p -h 0 -o c2 /src/cc.c    # cc.c compiles itself
strata$ c2 -p -h 0 -o c3 /src/cc.c     # ... and once more
strata$ cc -o cmp /src/cmp.c
strata$ cmp c2 c3
c2 c3: same
strata$ cmp c2.u c3.u
c2.u c3.u: same
strata$ cmp c2 /bin/cc
c2 /bin/cc: same
cc0(cc.c) = cc1The bootstrap compiler only has to be good enough to compile cc.c. It was taken further: it passes the same tests.
cc1(cc.c) = c2From here on the compiler is its own product. Its 108 KiB of code do not fit the 32 KiB instruction store: it pages itself.
c2(cc.c) = c3 = c2The fixed point. Any difference between these two would be a bug in the compiler that compiling a compiler is large enough to show.

02C as this machine sees it

Strata has no flat memory to point into. A C pointer is an address in the core's data Local Store; everything larger is behind a capability and is reached by a transfer. The compiler does not hide that.

40 KiB of data, 8 KiB of stack

int is 32 bits, long and pointers 64. Globals, the heap and string literals share the data Local Store; malloc hands out what the program left of it. System memory is an arena that far_read and far_write copy to and from.

Code larger than the machine holds

The instruction store is 32 KiB. With -p a program's functions are placed in 4 KiB units that the OS pages in on xcall; the compiler itself is built that way, its units in a second file the start-up code loads.

One pass, no assembler, no linker

Code is emitted while the source is parsed, with what has not yet had to be computed kept on a stack of value descriptors. The image is written directly; the run-time library is assembled once, at fixed addresses, and copied into every program.

No floating-point hardware

float and double are IEEE 754 in software, round to nearest even, in the library. The compiler folds constants with the same routines the programs call.

03The machine from C

The instructions only Strata has are intrinsics, one instruction each. Anything else is asm("..."): Strata assembly encoded in place, with {name} for a C object. The table of instructions is not in the compiler: the build makes it from the assembler, by assembling each instruction and seeing which bits each operand changes.

/* at file scope the labels of an asm are functions */
long twice(long x);
asm("twice:\n"
    "    add   a0, a0, a0\n"
    "    ret");

int main(void)
{
    long a = 3, b = 4, r = 0;

    asm("ld    t0, {a}\n"
        "ld    t1, {b}\n"
        "mul   t0, t0, t1\n"
        "sd    t0, {r}");
    printf("%ld %ld\n", r, twice(21));
    return 0;
}
/* a transfer to system memory and back, a
   capability's length: one instruction each */
long buf[2];

buf[0] = 0x1122334455667788;
__tput(1, (long)buf, 0, 0x1000, 8);
__tget(2, (long)(buf + 1), 0, 0x1000, 8);
__twait(6);

printf("%lx, the arena is %ld KiB\n",
       buf[1], __clen(0) >> 10);

Both are cut from lang/cc/examples/asm.c, which the tests compile and run in both code models. <strata.h> lists the intrinsics: transfers, far atomics, capabilities, CSRs, the supervisor call.

04The same source, on your machine

cc.c uses three things of StrataOS: the arena, files, and the library's floating-point routines. A hundred or so lines stand in for them on an ordinary machine, and the host's C compiler builds the same file into a cross compiler.

$ make build/strata-cc
$ build/strata-cc -o hi lang/cc/examples/hi.c     # a StrataOS program image, as cc would write it

The build makes the disk's cc this way, so no emulator is needed to build the system; the bootstrap above is the check that the two ways agree.

05Measured against other people's tests

The compiler was built against a ladder of 521 C programs from the test suites of two other compilers, scc (ISC licence) and lacc (MIT), sorted by what they need. Each is compiled and run inside StrataOS; exit status and output must match. Both compilers pass all of them, in both code models.
